Interview Process at MMT

0
Online Assessment (HackerEarth / HackerRank)
22 questions = 2 algorithmic coding + 20 MCQs on DBMS, OS, CN, Java OOP, SQL, aptitude. Medium difficulty. Used for campus & off-campus. Platform varies by batch.
1
DSA / Problem Solving Round (60 min)
2 coding questions on arrays, linked lists, trees, DP, graphs. Expect LeetCode Easy–Medium. Clean working code required with dry-run and complexity analysis. For SSE-2+, may have 2 full DSA rounds.
2
LLD / Machine Coding Round (60 min)
Design and code a real-world system with OOP. SOLID principles, design patterns (State, Builder, Strategy, Singleton), and concurrency handling are critical. MMT heavily emphasises Java — hard requirement.
3
HLD / System Design Round (60–90 min)
Design a distributed, travel-domain-relevant system. DB schema + SQL, scalability, concurrency, caching, API design, microservices. For senior roles this is the most gruelling round.
4
Managerial / Bar Raiser (for SDE-2+)
Project depth, innovative contributions, latency/scaling problems you have solved, architecture decisions. Director of Engineering sometimes takes this. Prepare STAR stories from your production work.
⚠️ MMT-Specific Signals
Java is a hard requirement at MMT — even if you're allowed Python/C++ in DSA, expect Java-specific follow-ups (records, generics, streams, concurrency). SOLID principles and design patterns are tested hands-on in LLD, not just theory. Idempotency and double-payment prevention are very commonly asked in HLD for the travel/payments domain.

LLD — Low Level Design Problems

MMT's LLD round expects working code, not just class diagrams. You'll be asked to code in IntelliJ/Eclipse live. Design patterns (State, Builder, Singleton, Strategy) are tested hands-on. Concurrency handling is a follow-up in almost every LLD.
💡 MMT LLD Tips
For every LLD: (1) Identify objects/entities first, (2) Define interfaces, (3) Apply the right design pattern, (4) Show how you handle concurrency (synchronized/AtomicXxx/ReentrantLock), (5) Make it extensible — the interviewer will add new requirements mid-round.

🔥 HighLLD
▾

State pattern: VendingMachineState interface → IdleState, HasMoneyState, DispensingState. VendingMachine holds currentState. Transitions on insertCoin(), selectItem(), dispense(), cancel().
Reported: SDE-2 LeetCode 2025, CodingKaro Java Developer
#2
Thread-Safe Builder Pattern (running two threads on it)
🔥 HighLLD
▾

SDE/SSE-2 Round 2 (LeetCode Discuss Oct 2024). Implement Builder pattern, spin up 2 threads running it. Key: synchronized is blocking — use AtomicReference or make builder immutable (each .withX() returns new builder).

Immutable builder approach: each setter returns a new builder with the updated field. Thread-safe because no shared mutable state. For mutable: use AtomicReference<T> on the final object.

Strategy & Preparation Tips

🎯 What MMT Actually Cares About (Backend)
Based on patterns across 20+ interview experiences: (1) Java is non-negotiable — they will probe Java internals even if you code DSA in Python. (2) Concurrency appears in every single round — DSA, LLD, HLD. (3) SOLID principles and design patterns are tested live, not just verbally. (4) Production-readiness: every design decision must have a rationale and trade-offs explained.

DSA Strategy

  • Priority topics: Arrays+Strings (Sliding Window, Two Pointer), Linked Lists, Trees (BFS/DFS/LCA), DP (subsequence patterns), Graphs (BFS/Dijkstra/Bridges), Heaps
  • Solve 2 questions per round — expect 60 mins per coding round. Budget 25 mins per question.
  • Always start with brute force → then optimise. MMT interviewers appreciate the thought process over jumping to optimal.
  • Always analyse time and space complexity. Do a dry-run on a sample test case when asked.
  • For LeetCode prep: focus on Medium difficulty. Hard is rarely asked; Easy is used only as warmup at senior levels.
  • Recommended list: LeetCode Top 100 Liked + all problems tagged "MakeMyTrip" on LeetCode

Java Preparation Checklist

  • ✅ Java 8–17 features: Streams, Optional, Records (Java 16+), sealed classes
  • ✅ HashMap internals: hashing, load factor, rehashing, why size is power of 2
  • ✅ Concurrency: synchronized, volatile, AtomicXxx, ReentrantLock, Semaphore, CountDownLatch
  • ✅ ExecutorService: ThreadPoolExecutor, CompletableFuture, ForkJoinPool
  • ✅ Collections: ConcurrentHashMap vs HashMap, CopyOnWriteArrayList
  • ✅ Garbage Collection: G1GC basics, when to worry about GC pauses
  • ✅ Spring: bean lifecycle, @Transactional propagation, AOP, interceptors
  • ✅ Practice coding design patterns live in Java — not just knowing them theoretically

System Design Preparation

  • ✅ Go deep on: Ticket Booking (concurrency, optimistic locking), URL Shortener, Rate Limiter, Distributed Cache
  • ✅ Know the trade-offs: SQL vs NoSQL, REST vs gRPC vs Kafka, sync vs async
  • ✅ Practice DB schema design: normalisation, indexing, query optimisation
  • ✅ Idempotency keys, outbox pattern, and saga are table-stakes for payments/booking domain
  • ✅ Be ready to defend every decision — Why this DB? Why this cache strategy? What breaks at 10x load?

MMT-Specific Resume Prep (SDE-2+)

  • Prepare 3 STAR stories: one latency fix, one architecture change you proposed, one innovative feature you shipped
  • For every tech in your resume (Redis, Kafka, Elasticsearch): know why you chose it, what alternatives existed, what trade-offs were made
  • Quantify achievements: "reduced API response time by 98%" is exactly what MMT probes on
  • Know your Spring Boot microservice flow end-to-end: request → controller → service → repository → DB → cache
  • Be ready for: "Describe a production incident and how you debugged it" with Kibana/Grafana as tools
⚠️ Common Failure Points at MMT
  • Using synchronized everywhere in LLD — interviewers want you to know about non-blocking alternatives (AtomicXxx, ConcurrentHashMap)
  • Skipping design patterns in LLD — they will notice and penalise
  • Not having a clear idempotency/double-payment answer ready (critical for travel/payments)
  • Weak on Java internals despite listing Spring Boot on resume
  • Not preparing STAR stories for the managerial/director round — this is where SDE-2 candidates often fail
